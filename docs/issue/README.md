## 남아 있는 근본 원인

`false-fiber-warning` 은 해결됐다. 나머지 셋은 완화 단계다. 뿌리에 있는 것은 두 가지다.

**1. 스트림 델타에서 무엇이 최종 응답인지 판별하지 못한다**
→ `assistant-message-duplication` 의 수정 A. 지금은 "마지막이 최종"이라는 가정에 기댄다.
생성 중 스트림을 한 번 떠서 `content.content_type` · `recipient` · `metadata` 중 무엇이 판별자인지 확정해야 한다.
`:health` 의 대체 횟수가 예상보다 크면 가정이 틀렸다는 신호다.

**2. 대화 원본을 DOM 말고 다른 데서 못 읽는다**
→ `partial-thread-harvest` 의 근본 해결. `/backend-api/conversation/<id>` 와
`/backend-api/f/conversation/<id>` 는 둘 다 404 였다(경로 변경으로 보임).
이 경로를 다시 찾으면 부분 렌더 문제가 통째로 사라진다.
