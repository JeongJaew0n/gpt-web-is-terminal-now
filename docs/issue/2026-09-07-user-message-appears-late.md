# 내 질문보다 '생각 중' 이 먼저 뜬다

질문을 보내면 `생각 중` 이 먼저 나타나고, 잠시 뒤에 내가 보낸 질문이 그 위에 끼어든다.
순서가 뒤집혀 보인다.

## 실측 (2026-09-07)

전송 버튼을 누른 순간을 0ms 로 잡고, 50ms 간격으로 원본 DOM 과 우리 shadow root 를
함께 관찰했다. 빌드 `2026-09-07 22:40`.

**1회차 — 간단한 질문**

```
 2062ms  원본 중단버튼 등장
 3549ms  우리 질문 등장
 5138ms  원본 질문 등장
```

**2회차 — 추론이 붙는 질문**

```
 1000ms  원본 중단버튼 등장
 1003ms  원본 질문 등장
 1003ms  우리 응답 블록 등장
 1999ms  우리 질문 등장
```

**[확정] 원본은 질문을 즉시 그리고(1003ms), 우리는 약 1초 늦게 그린다(1999ms).**

**[확정] `생각 중` 을 켜는 신호는 원본 중단버튼이고, 그건 1000ms 에 이미 있다.**
즉 우리 질문이 화면에 오르기 **1초 전**부터 `생각 중` 을 띄울 조건이 성립한다.
그 1초 동안 화면에는 답을 기다리는 표시만 있고 정작 질문은 없다.

## 왜 늦나

**우리 스크롤백에 사용자 메시지가 들어오는 경로가 하나뿐이고, 그게 늦다.**

```
Enter → commands.run() (명령 아님)
      → compose.send()            원본 컴포저에 주입하고 전송 버튼을 누른다
      → (여기서 우리는 아무것도 기록하지 않는다)
      ⋮
      → 서버가 응답을 시작
      → SSE 의 input_message 이벤트
      → tap.js  post('user', {id, text})       ← src/main/tap.js:171
      → index.js GT.on('user', …)              ← src/content/index.js:152
      → store.userSent(text, id)               ← 이때 비로소 화면에 뜬다
```

`compose.send()` 는 원본 컴포저에 글자를 넣고 전송 버튼을 누를 뿐, **우리 store 에는
아무것도 남기지 않는다.** 사용자 메시지는 서버가 스트림을 열고 `input_message` 를
돌려줄 때까지 존재하지 않는다.

반면 원본 UI 는 누른 즉시 자기 상태에 넣고 그린다(낙관적 렌더). 그래서
원본은 1003ms, 우리는 1999ms 다.

`생각 중` 은 원본 중단버튼을 보고 켜지므로(깜빡임을 없애며 그렇게 바꿨다 —
[2026-09-07 깜빡임 건](2026-09-07-thinking-indicator-flicker.md)) 그 1초 구간에
질문 없이 먼저 뜬다.

## 수정 방안

**보낸 즉시 우리도 기록한다.** 원본이 하는 것과 같은 낙관적 렌더다.

```js
const r = await GT.compose.send(text);
if (r.ok) GT.store.userSent(text);        // id 없이 먼저 올린다
```

`store.userSent(text, id)` 는 id 가 없으면 `local-<시각>` 으로 레코드를 만든다.
그대로 두면 잠시 뒤 SSE 의 `input_message` 가 진짜 id 로 **한 번 더** 부르면서
같은 질문이 두 줄이 된다. 그래서 합치는 규칙이 필요하다.

- `userSent(text, id)` 가 불렸을 때, 마지막 레코드가 **같은 본문의 `local-` 사용자
  메시지**면 새로 만들지 말고 그 레코드의 id 만 진짜 id 로 바꾼다
- id 를 바꾸면 `byId` 도 옮겨야 한다. 안 옮기면 그 뒤의 델타가 레코드를 못 찾는다

전송이 실패하면(`r.ok === false`) 올리지 않는다. 지금도 그때는 경고만 남긴다.

수확과의 관계도 봐야 한다. `applyHarvest` 의 병합 분기는 수확에 없는 레코드를
'아직 안 그려진 것'으로 보고 지키므로, `local-` 레코드는 살아남는다. 다만 진짜 id 로
갈아타기 전에 수확이 돌면 같은 질문이 두 벌 보일 수 있다 — 합치는 규칙이 id 뿐 아니라
**본문 일치**도 보게 하는 이유다.

## 고친 방법 (2026-09-07)

- `index.js` — `compose.send()` 가 성공하면 곧바로 `store.userSent(text)` 를 부른다.
  id 없이 올리므로 `local-<시각>` 레코드가 된다
- `store.upsert()` — 진짜 id 를 가진 **사용자** 메시지가 들어올 때, 같은 본문의
  `local-` 레코드가 있으면 새로 만들지 않고 그 레코드에 id 를 갈아 끼운다.
  `byId` 도 함께 옮긴다

합치는 규칙을 `userSent` 가 아니라 **`upsert` 에 둔 이유**가 있다. 진짜 id 는 두 경로로
들어온다 — SSE 의 `input_message`, 그리고 DOM 수확. 둘 다 `upsert` 를 지나므로
한 곳만 막으면 된다. `userSent` 에만 뒀다면 수확이 먼저 도는 경우에 두 줄이 된다.

## 회귀 방지

`test/store.test.mjs` 20 → 34건.

- 보낸 직후 화면에 올라가고 임시 id 를 단다
- 그 뒤 `input_message` 가 진짜 id 로 와도 줄이 하나고, 같은 레코드에 id 만 바뀐다
- 임시 id 는 `byId` 에서 지워지고 진짜 id 로 찾힌다
- 수확 경로로 들어와도 합쳐진다
- 본문이 다르면 합치지 않는다. 턴이 다르면(응답이 끼면) 같은 말이어도 두 줄이다
- 전송이 실패하면 올리지 않는다
