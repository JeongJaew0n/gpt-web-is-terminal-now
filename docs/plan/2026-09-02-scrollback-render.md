# 스크롤백 렌더 개선 — 안 바뀌면 안 그리고, 바뀐 것만 갈아끼운다

- 상태: **구현됨** (2026-09-02) — 브라우저 확인 대기
- 배경: `docs/issue/2026-09-02-selection-lost-on-rerender.md`
- 범위: 이슈의 고칠 방향 **1·2번**. 3번(선택 중 재렌더 보류)은 이번에 하지 않는다.

## 지금

```js
render() {                       // 1초마다 + store 변경마다
  ui.scroll.textContent = '';    // 59블록 · 하위 1341노드를 버리고
  messages.forEach(…)            // 처음부터 다시 만든다
}
```

바뀐 게 없어도 돈다. 선택 앵커가 사라지고, 대화가 길수록 매초 수천 노드를 만들고 버린다.

## 무엇을 바꾸나

### 1. render 를 둘로 가른다

| | 내용 | 언제 |
|---|---|---|
| `renderChrome()` | 상단바·탭·입력줄 메타·상태줄·시계 | 매 틱 (싸다) |
| `renderScrollback()` | 대화 블록 | **서명이 바뀌었을 때만** |

1초 틱의 목적은 시계와 경과시간이다. 그걸 위해 본문을 갈아엎을 이유가 없다.

### 2. 메시지 단위로 갈아끼운다

노드를 `Map(key → {el, sig})` 로 들고, 서명이 같으면 **그 노드를 그대로 재사용**한다.

```
key   메시지 id (시스템 행은 발급한 고유 id)
sig   role · text.length · streaming · model · thinking · parts수 · configEpoch
```

스트리밍 중에는 마지막 블록의 `text.length` 만 바뀐다 → **그 블록 하나만 다시 만든다.**
앞쪽 블록의 DOM 노드는 손대지 않으므로 거기 걸린 선택이 살아남는다.

### 3. 타임스탬프는 자리에서 고친다

상대 시각("3분 전")은 시간이 지나면 표시가 달라진다.
이걸 서명에 넣으면 1분마다 블록이 통째로 교체된다 — 선택을 다시 깨뜨린다.

그래서 **서명에서 빼고**, 노드 레코드에 스탬프 엘리먼트 참조를 들고 있다가
틱마다 `textContent` 만 갈아준다. 노드 교체가 없다.

## 설계 결정

**서명에 무엇을 넣는가**가 이 작업의 전부다. 빠뜨리면 낡은 내용이 남는다.
`turnUser`/`turnAssistant` 가 읽는 값을 전부 넣는다 —
`role · text.length · streaming · model · thinking · parts.length`.

`text.length` 로 충분한가? 같은 길이로 내용만 바뀌는 경우(예: fiber 교정)가 있다.
그래서 **길이 + 앞뒤 8자**를 함께 넣는다. 전체 해시는 긴 대화에서 매 틱 비용이 된다.

설정 변경(`gutter.markers`·`wrap.columns`·`timestamps`)은 렌더 결과를 바꾼다.
개별로 추적하지 않고 **configEpoch** 하나를 두고 설정이 바뀔 때마다 올린다 → 그 틱에 한 번 전체 재구성.

## 완료 조건

1. 아무것도 안 바뀐 상태에서 5초간 **스크롤백 DOM 변경이 0**
2. 스트리밍 중 **마지막 블록만** 교체되고 앞 블록의 노드 동일성이 유지된다
3. 앞쪽 문단에 건 선택이 스트리밍 중에도 **살아남는다**
4. 상대 타임스탬프는 계속 갱신된다 (노드 교체 없이)
5. 설정을 바꾸면 한 번 전체 재구성된다
6. 대화 전환·수확 시 낡은 노드가 남지 않는다

## 테스트 계획

순수 함수로 뺀 부분을 직접 검사한다.

- `signature` — 텍스트가 바뀌면 서명이 바뀐다 / 같으면 같다 / 길이가 같고 내용이 다른 경우도 잡는다
- `reconcile` — 뒤에 추가 / 중간 삭제 / 순서 유지 / 전체 교체 각각에서 **최소 연산**을 내는가
- 재사용 — 바뀌지 않은 key 는 `keep`, 바뀐 key 는 `replace`
- configEpoch 가 오르면 전부 `replace`

DOM 적용부는 얇게 두고, 정적 검사로 `textContent = ''` 가 스크롤백에서 사라졌는지 확인한다.

## 구현 메모

- **id 없는 메시지를 건너뛰려다 되돌렸다.** 서명 키를 만들 때 `if (!m.id) return;` 으로
  짰는데, 그러면 그 메시지가 **화면에서 조용히 사라진다.** 위치 기반 키(`i:<index>`)로
  대신 그린다. 이 저장소에서 반복해 만난 부류의 실수라 테스트로 못 박았다.
- 구분자 대신 `JSON.stringify` 로 서명을 만든다. 본문에 어떤 문자가 들어와도 경계가 흐려지지 않는다.

## 남은 것 — 선택 중 재렌더 (3번)

1·2번으로 앞쪽 블록은 손대지 않으므로 대부분 해결된다.
**스트리밍 중인 마지막 블록 안에 걸린 선택**은 여전히 깨진다.

여기에는 '보류'보다 나은 선택지가 있다(주류 방법도 아니다).

| 방법 | 평 |
|---|---|
| **스트리밍 렌더 스로틀** | 매 델타마다가 아니라 100~150ms 로 묶는다. 창이 크게 줄고 덤으로 성능도 좋아진다. **추천** |
| 선택 저장·복원 | 오프셋을 재고 다시 만든 뒤 복원. 마크다운 구조가 바뀌면 매핑이 어긋난다 |
| 선택 중 그 블록만 보류 | 위 둘보다 나을 이유가 없다 |

먼저 1·2번을 써보고 실제로 거슬리면 스로틀을 넣는다.
- 가상 스크롤 — 지금 규모(수십 블록)에서는 과하다.

## 위험

- **서명 누락** → 낡은 내용이 화면에 남는다. 증상이 조용해서 알아채기 어렵다.
  그래서 서명 함수를 순수 함수로 빼고 테스트를 먼저 쓴다.
- **노드 재사용과 이벤트 핸들러** — 코드블록의 `[y]ank` 등은 블록 생성 시 붙는다.
  재사용하면 핸들러도 함께 재사용되므로 문제없지만, 핸들러가 `m` 을 클로저로 잡고 있으면
  낡은 값을 참조한다. 재사용 시 데이터가 같다는 게 서명의 보장이므로 성립하지만,
  **서명에 없는 필드를 핸들러가 읽으면 깨진다** — 3번 항목에서 같이 점검한다.
